# SafeCapital Dashboard 客户演示流程与网站接入说明

> 1.4 新增关注股票、多选、统一日期、详情和当前选择导出。Presentation 请优先按 [关注股票演示流程](PRESENTATION_WATCHLIST.md) 操作；下文保留更深入的输入、输出及接入讲解。

适用版本：Dashboard 1.4。更新日期：2026-11-02（澳大利亚悉尼）。

本文可作为演示者的操作清单和讲解稿。建议演示 12–15 分钟，另留时间讨论客户的接入方式。示例数值已与当前本地服务核对；之后更换结果版本时，以页面实际数据为准。

## 一、这次演示要让客户理解什么

演示围绕三个问题展开：数据从哪里来、模型输出什么、客户怎样使用这些结果。

可以用下面这段话开场：

> 我们将 SafeCapital 做成了一个可以独立使用、也可以集成进网站的研究模块。今天会先展示项目的输入数据，再查看同一只股票的模型排名和组合回测表现，最后展示查询接口和网站嵌入方式。当前页面读取的是已有数据与已验证的历史运行结果。

演示时区分两条流程：

```text
已有财务因子 → 周内百分位转换 → 已保存模型 → 股票排名
股票排名 + 历史价格 + 策略规则 → 历史回测 → 资金曲线与汇总指标
```

Dashboard 负责读取和展示这些输入、输出。打开页面、切换日期或搜索股票，不会重新训练模型或重新运行回测。

## 二、演示前准备

### 1. 打开本地服务

如果当前网页已经能够正常显示数据，保持现有服务运行即可，不要重复启动。

如果服务没有运行，在项目根目录打开终端，执行：

```bash
.venv-dashboard/bin/python dashboard/start.py
```

保持终端窗口运行，浏览器打开 [Dashboard 首页](http://127.0.0.1:8000/)。首次安装或环境尚未准备好时，按 [Dashboard README](../README.md) 操作。

### 2. 提前准备三个页面

| 页面 | 地址 | 演示用途 |
|---|---|---|
| 独立 Dashboard | http://127.0.0.1:8000/ | 输入、排名、回测和下载 |
| 网站嵌入示例 | http://127.0.0.1:8000/embed-example.html | 展示模块放入外层网站的效果 |
| API 文档 | http://127.0.0.1:8000/api/docs | 给客户开发者查看接口 |

API 文档界面依赖外部 CDN，建议演示前打开确认。若无法加载，可使用项目内的 [OpenAPI JSON](openapi.json) 和 [接口说明](API_V1.md)，Dashboard 本身的数据展示不依赖这份在线文档界面。

### 3. 检查演示状态

- 根据客户选择页面顶部的“中文 / English”。本稿使用中文按钮名称；英文界面按同一布局操作。切换语言不会清空查询条件，刷新后也会记住语言。英文演示可直接打开 `http://127.0.0.1:8000/?lang=en`；英文嵌入链接使用 `?embed=1&lang=en`。

- 选择默认“结果版本”，确认页面显示“文件哈希校验通过”。演示过程中保持同一结果版本。
- “输入数据”选择“模型因子输入”“与本次输出对齐”，日期设为 `2026-08-28`，搜索框先留空。
- “股票排名”清空搜索；图表选择“账户资金”和“全部”。
- 本地地址仅供本机访问。远程会议通过屏幕共享演示，不把 `127.0.0.1` 当作客户可以直接打开的网站地址。

## 三、正式演示：逐步操作与讲解

### 第 1 步：介绍总体结果（约 1 分钟）

**怎么操作**

1. 打开首页，点击顶部“组合表现”。
2. 指出“结果版本”和“文件哈希校验通过”。
3. 简单展示组合指标，暂时不深入解释每个图表。

**怎么介绍**

> 这里展示的是一次已完成并通过校验的历史运行。结果版本用于区分不同运行记录，页面上的数据来自真实结果文件。我们先看总体表现，再回到输入数据，解释这些结果是怎样关联起来的。

**当前应看到的结果**

| 指标 | 当前示例值 |
|---|---:|
| 初始资金 | 100,000 |
| 期末账户资金 | 149,330.61 |
| 累计收益 | 49.33% |
| 年化收益 | 10.44% |
| 最大回撤 | -24.88% |
| 夏普比率 | 0.543 |
| 回测覆盖 | 210 个信号周 |

资金沿用原回测计价单位，不自行称为美元或澳元。累计收益是整个回测区间的结果，不是某一年的收益；历史结果不代表未来收益。

### 第 2 步：展示模型因子输入（约 2 分钟）

**怎么操作**

1. 点击顶部“输入数据”。
2. 选择“模型因子输入”。
3. 保持“查看范围”为“与本次输出对齐”，输入日期选择 `2026-08-28`。
4. 在“搜索输入股票代码”中输入 `ANF`。
5. 横向滚动表格，展示五个因子；将鼠标停在字段标题或数值上，可以查看对应字段名或完整值。

**怎么介绍**

> 模型使用项目已经准备好的周度数据。这里一行代表一只股票在一个信号日期的记录，日期和股票代码共同标识这条数据。表格展示的是模型做周内百分位转换之前的因子数值。
>
> 模型包含三个组件，共使用 45 个已保存的模型快照。当前演示读取的是与这次运行对应的输入和结果。

| 展示字段 | 接口字段 | 讲解方式 |
|---|---|---|
| 信号日期 | date | 这条记录属于哪一个信号周 |
| 股票代码 | ticker | 用于识别股票并关联输出 |
| 公司名称 | stock_name | 方便阅读的展示信息 |
| 营收同比增长 | revenue_growth_yoy | 描述营收增长情况 |
| 经营盈利能力 | operating_profitability | 描述经营盈利情况 |
| 现金流 / 资产 | cashflow_to_assets | 描述现金流相对资产的水平 |
| 负债 / 资产 | debt_to_assets | 描述负债相对资产的水平 |
| 资产同比增长 | asset_growth_yoy | 描述资产规模增长情况 |

强调表格值是因子数值，不是模型给出的未来收益率；页面保留六位小数，接口返回数值，CSV 下载保留原始文件。

### 第 3 步：解释输入范围和历史价格（约 2 分钟）

**怎么操作**

1. 指出输入区顶部的“源文件记录”和“与本次预测输出对齐的记录”。
2. 将“查看范围”改为“完整源文件”，日期选 `2015-09-04`。切换范围会清空股票搜索。
3. 展示表格中的“不在预测区间”，解释这些输入没有对应的本次预测输出。
4. 切换“回测价格输入”，将范围改回“与本次输出对齐”，日期选 `2026-08-28`，搜索 `ANF`。
5. 展示“下一周开盘代理价”和“下一周收盘代理价”，必要时横向滚动表格。

**怎么介绍**

> 源文件的历史范围，比这次输出覆盖的范围更长，所以我们把完整数据和与本次输出对齐的数据分开显示。不是所有源文件行都会出现在这次预测或回测结果中。
>
> 价格输入用于历史回测。这里的开盘和收盘代理价对应信号日期之后的持有期，用来模拟执行和期末计价；它们不是本次模型排名的财务因子。更早的价格记录也可能用于策略的历史回看过滤。

| 范围 | 当前记录数 | 信号周数 | 日期范围 |
|---|---:|---:|---|
| 每份完整输入源文件 | 17,353 | 574 | 2015-09-04 至 2026-08-28 |
| 与预测输出对齐的因子记录 | 13,517 | 366 | 2019-08-30 至 2026-08-28 |
| 与回测输出日期/股票键对齐的价格记录 | 8,354 | 210 | 2022-08-26 至 2026-08-28 |

当前源文件股票池为 40 只，不表示每个历史日期都有全部 40 只股票。“输出对齐”也不表示回测只使用这些价格行，历史回看可能使用更早数据。

### 第 4 步：从一条输入跳到对应输出（约 1 分钟）

**怎么操作**

1. 切回“模型因子输入”。
2. 确认范围为“与本次输出对齐”，日期 `2026-08-28`，再次搜索 `ANF`。切换输入类别会清空搜索；对齐模式仍使用统一历史日期。
3. 点击 ANF 行右侧的“查看输出”。
4. 页面跳到“股票排名”，日期和股票筛选自动同步。

**怎么介绍**

> 这一步展示输入和输出如何关联。我们用信号日期加股票代码定位同一条股票记录，点击后就能看到它在当周的模型排名，而不需要手动查找结果文件。

**当前 ANF 应看到的输出**

| 字段 | 当前示例值 |
|---|---:|
| 信号日期 | 2026-08-28 |
| 股票代码 | ANF |
| 集成排名 | 30 |
| 集成得分（页面显示） | 0.3417 |
| 组件 1 百分位 | 30.0% |
| 组件 2 百分位 | 32.5% |
| 组件 3 百分位 | 40.0% |

补充说明：

> 集成得分来自三个组件周内百分位的等权平均，用于比较同一周股票的相对排序。0.3417 不能解释为预计上涨 34.17%，也不是上涨概率。

随后清空排名搜索，展示当周完整排名和分页。当前示例中 SCL 为第 1 名。排名是策略过滤前的模型结果，不等同于实际持仓或买入指令。

### 第 5 步：展示组合层面的输出（约 2 分钟）

**怎么操作**

1. 点击“组合表现”，回到“看见资金的每一步”图表。
2. 依次点击“账户资金”“每周收益”“历史回撤”。
3. 鼠标移动到曲线位置，展示日期和数值提示。
4. 切换“末 52 周”，再切回“全部”。
5. 简要展示旁边的策略说明。

**怎么介绍**

> 股票排名回答的是当周股票的相对顺序。组合回测在排名基础上加入历史过滤、选股、资金分配和交易成本，回答这些规则在历史区间中形成了怎样的账户表现。
>
> 账户资金曲线展示每个持有期末的资金，每周收益展示周度变化，历史回撤展示相对历史资金峰值的下降幅度。切换图表区间只改变查看范围，顶部汇总指标仍然对应完整的 210 周回测。

如客户问策略规则，可简述：采用 `Top5_NoLoss13w`，先做历史 13 周收益过滤，再按模型排名选取最多五只符合条件的股票，每只目标权重 20%，并考虑整数股、现金和交易费用。若不足五只，保留相应现金。

不要将“下载全部排名”介绍为持仓或订单导出；完整排名下载保留原始结果；关注区可导出当前选择的输入、排名和真实配置，但不提供逐笔订单。

### 第 6 步：展示来源、校验与下载（约 1 分钟）

**怎么操作**

1. 点击“验证与下载”。
2. 展示预测记录数、预测周数、回测周数，以及运行完成时间和结果编号。
3. 点击“回测汇总”下载 CSV；根据客户兴趣再展示“每周资金”或“运行校验清单”。
4. 说明完整排名在“股票排名”的“下载全部排名”处下载，输入在输入区的“下载完整输入 CSV”处下载。

**怎么介绍**

> 页面数据可以追溯到具体运行和原始结果文件。客户不仅能在页面中查看，也能下载文件继续分析。文件哈希校验用于确认所展示的文件与记录一致。

区分“运行完成时间”和“数据覆盖日期”：前者表示程序何时完成，后者表示历史样本覆盖到哪一天。

输入 CSV 下载始终为完整源文件，不随页面日期、股票筛选或分页裁剪。原始输入 CSV 还包含 `target1`、`target2` 等研究标签；这些标签不参与预测或选股，输入查询接口不会把它们作为模型因子返回。

### 第 7 步：展示客户可调用的接口（约 1–2 分钟）

**怎么操作**

1. 回到“输入数据”，保持 ANF 和 `2026-08-28` 的筛选条件。
2. 展示“当前输入查询接口”，点击“复制地址”或“打开 JSON”。
3. 点击顶部“输入输出接口”，依次展示“输入清单 JSON”“当前日期输出排名”“输出汇总 JSON”。
4. 如有客户开发者在场，打开“完整 API 文档”。

**怎么介绍**

> 页面使用的数据也可以通过接口读取。客户可以继续使用这套 Dashboard，也可以用自己的界面展示同样的数据。输入查询支持日期、股票、范围和分页；输出接口提供排名、资金序列和汇总。
>
> 当前“输入接口”的意思是查询系统已有输入。它不是上传新数据或发起新预测的接口。

“当前日期输出排名”链接按所选日期返回第一页排名，不继承排名表中的股票搜索；展示 ANF 的对应关系以第 4 步的表格或带 `q=ANF` 的接口查询为准。

技术演示可选步骤：在项目根目录另开终端执行以下现成示例，不必在会议现场手写请求。

```bash
node dashboard/examples/client.mjs http://127.0.0.1:8000/
```

需要 Node.js 22 或更高版本。示例会自动获取默认运行 ID 和最新日期，再打印该日期首名股票的输入因子、价格、排名、回测汇总及下载地址。当前该股票为 SCL。

### 第 8 步：展示嵌入效果并收集接入需求（约 1–2 分钟）

**怎么操作**

1. 在“输入输出接口”区点击“预览嵌入模式”，展示去掉外层导航后的 Dashboard。
2. 点击“查看网站嵌入示例”，展示“客户网站 · 演示外壳”中的模块。
3. 在框内切换日期或搜索股票，说明嵌入后仍保留交互功能。

**怎么介绍**

> 这是我们准备的模拟网站外壳，里面通过 iframe 加载同一个 Dashboard。客户可以在现有网站中新增研究模块；如果希望完全采用自己的界面，也可以选择调用 API。
>
> 这个页面验证了本地嵌入方式。正式接入还需要确定服务地址、客户网站域名和登录要求，并在客户的实际环境中联调。

## 四、后续怎样接入客户的网站

### 方案 A：嵌入完整 Dashboard

适用于客户认可现有页面，希望尽快增加一个可使用的研究模块。

| 工作 | 具体内容 |
|---|---|
| 运行模块 | 将 Python 服务和前端页面运行在双方确定的环境中；可使用原生 Python 服务，Docker 不是必要条件 |
| 提供地址 | 为服务提供客户能够访问的地址，正式网站通常通过 HTTPS 网关访问 |
| 配置嵌入 | 在 SafeCapital 配置中填写公开访问地址和允许嵌入的客户网站 origin |
| 添加页面 | 客户网站新增导航入口或页面，放入 iframe |
| 联调验收 | 在客户页面中检查加载、滚动、筛选、下载、窄屏显示，以及需要时的登录状态 |

示例代码如下，域名是占位符，正式接入必须替换：

```html
<iframe
  src="https://research.example.com/?embed=1"
  title="SafeCapital 历史策略研究"
  width="100%"
  height="1400"
  style="border: 0; border-radius: 16px"
  loading="lazy">
</iframe>
```

对应配置示例：

```toml
public_url = "https://research.example.com/"
embed_origins = "https://client.example"
api_origins = ""
```

`embed_origins` 填写协议、域名及必要端口，不含页面路径或尾部斜线。客户网站自身的 `frame-src` 策略也需要允许 Dashboard 地址。iframe 内部的页面和 API 同源，此方式通常不需要为客户外层页面开放 API 跨域访问。

### 方案 B：客户自建界面，调用输入输出 API

适用于客户希望使用自己的布局、组件和业务页面。

客户首先请求 `GET /api/cs5_6_equity/v1/runs`，读取 `default_run_id`，再以该 ID 查询数据。不要把本机运行目录名写死在客户代码中。

| 功能 | GET 接口路径 |
|---|---|
| 可用结果版本 | `/api/cs5_6_equity/v1/runs` |
| 输入目录、字段和覆盖范围 | `/api/cs5_6_equity/v1/runs/{run_id}/inputs` |
| 模型因子查询 | `/api/cs5_6_equity/v1/runs/{run_id}/inputs/factors/rows?date=2026-08-28&q=ANF&scope=output` |
| 价格查询 | `/api/cs5_6_equity/v1/runs/{run_id}/inputs/prices/rows?date=2026-08-28&q=ANF&scope=output` |
| 完整因子 CSV | `/api/cs5_6_equity/v1/runs/{run_id}/inputs/factors/download` |
| 完整价格 CSV | `/api/cs5_6_equity/v1/runs/{run_id}/inputs/prices/download` |
| 股票排名 | `/api/cs5_6_equity/v1/runs/{run_id}/rankings?date=2026-08-28&q=ANF` |
| 回测汇总与来源 | `/api/cs5_6_equity/v1/runs/{run_id}/overview` |
| 每周资金序列 | `/api/cs5_6_equity/v1/runs/{run_id}/equity` |
| 汇总 CSV | `/api/cs5_6_equity/v1/runs/{run_id}/downloads/summary` |

输入查询的 `scope=output` 表示与该次输出对齐，`scope=source` 表示完整源文件范围。查询使用 `page` 和 `page_size` 分页，页码从 1 开始，单页最多 100 条。`q` 是股票代码子串筛选，准确关联仍使用 `date + ticker`。

若客户浏览器从不同 origin 直接请求 SafeCapital API，需要配置精确的 `api_origins`，例如：

```toml
api_origins = "https://client.example"
```

客户后端直接调用 API 不依赖浏览器 CORS。完整字段、错误处理和示例见 [API_V1.md](API_V1.md)、[openapi.json](openapi.json) 与 [client.mjs](../examples/client.mjs)。

### 两种方案共同需要明确的事项

1. **服务在哪里运行**：客户服务器、我方维护环境，还是其他约定环境；谁负责启动、更新和维护。
2. **客户要哪种界面**：嵌入现有 Dashboard，还是调用 API 自建页面。
3. **实际访问地址**：Dashboard 服务地址、客户网站 origin、测试环境地址。
4. **是否需要登录**：当前模块没有独立账号或客户 SSO；如果要求登录后访问，需要确定认证方案并同时覆盖页面、API 和下载。域名白名单不等于登录保护。
5. **数据如何更新**：当前版本读取启动时快照，更换匹配的输入和已验证结果后需要重启服务；自动获取新数据和定时计算属于后续需求。

第一次会议不需要客户立即给出所有技术参数。先确定接入方式和技术联系人，再安排开发人员确认环境并联调。

## 五、现场常见问题与建议回答

| 客户问题 | 建议回答 |
|---|---|
| 这是实时行情或实时预测吗？ | 当前展示的是已有数据和已验证的历史结果；实时更新需要另行接入数据和计算流程。 |
| 可以现在上传一份 CSV 看新结果吗？ | 当前输入接口只读，提供已有因子和价格的查询。上传、校验、新预测及任务状态需要作为后续功能开发。 |
| 为什么输入行数和预测行数不同？ | 源文件覆盖更长的历史；预测和回测各有自己的有效区间。页面已经分别标明覆盖范围。 |
| 模型得分 0.9 是否代表上涨 90%？ | 不是。它是相对排名得分，用于当周股票间比较。 |
| 排名前五是否就是实际持仓？ | 排名在策略过滤前生成；实际回测还需要历史过滤、资金分配、现金和费用规则。 |
| 数据是真实运行结果吗？ | 是项目已有输入及已验证的历史回放输出，可以通过结果编号、校验记录和下载文件核对。 |
| 为什么刷新页面后数据没有更新？ | 服务在启动时读取一致的数据快照，更新磁盘文件后需要重启服务。 |
| 能把这个本地链接发给我们吗？ | 本地地址只指向当前电脑。我们可以交付软件包供客户运行，或在约定环境中提供可访问的服务地址。 |
| 我们网站不是 React，能接入吗？ | 可以选择 iframe 或 HTTP API；不要求客户网站使用与 Dashboard 相同的前端框架。实际接入仍需按网站环境联调。 |
| 必须安装 Docker 吗？ | 不需要。当前本地版使用 Python 原生服务运行。 |

## 七、现场故障的快速处理

| 情况 | 处理方式 |
|---|---|
| 网页无法打开 | 检查启动终端是否仍在运行，确认访问端口与启动参数一致。 |
| 提示端口已占用 | 先检查原服务是否已经可用；确实需要新端口时使用 `--port 8001`，演示页面地址同步改成 8001。 |
| 股票查询为空 | 确认日期为有效信号周、搜索代码正确；切换范围或类别后重新确认筛选条件。 |
| 输入显示不可用，输出仍正常 | 输入文件缺失或与该结果身份不一致。会前检查匹配文件和运行版本，不在演示现场替换模型或重新训练。 |
| API 文档打不开 | 使用本地 OpenAPI 文件和 API_V1.md；也可通过页面“打开 JSON”直接展示响应。 |
| 演示时间不足 | 保留“总览 → ANF 输入 → 查看输出 → 嵌入示例”四步，接口细节留给客户开发者会后查看。 |
